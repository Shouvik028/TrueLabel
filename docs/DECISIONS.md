| 17 | 2026-09-27 | Mock catalogue data is split into typed source data (`scripts/mock-data/source/`) and a generated, committed fixture (`apps/mobile/src/data/mock/fixture.json`) written by `scripts/generate-mock-data.ts`, which calls `packages/core`'s `computeProductScore`/`computeFreshness` against a fixed `asOf` date. A Vitest drift test rebuilds the fixture in memory and fails if it differs from the committed file. The mobile app only ever imports the fixture, never the source data or the scoring engine (CLAUDE.md hard constraint #4). Source data lives outside `apps/mobile` because Phase 3's `supabase/seed.sql` generator will reuse the same files | Guarantees the app can never show a score the engine didn't compute, keeps mock and future seed data as one source of truth, and makes any drift between source data and the shipped fixture a test failure instead of a silent mismatch | Compute scores inline in the mock repository (would violate constraint #4 if ever ported to a real client bundle); hand-type scores into the fixture (defeats the point of testing against the real engine); keep source data under `apps/mobile` (ties Phase 3's seed script to the mobile workspace) |
